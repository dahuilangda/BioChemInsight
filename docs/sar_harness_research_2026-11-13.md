# SAR harness 研究与实现审查

日期：2026-11-13。目标是文献、专利中的可追溯构效关系，重点保留自研 MolSight 的多肽与环肽识别能力。本文区分已实现机制、实际回归结果和仍需验证的科学正确性；没有将单篇文献的成功当成泛化证明。

## 研究判断

适合本项目的方向是专用结构模型、文档视觉理解、确定性化学工具和可恢复控制循环协作。Doc2SAR 的研究也指出，通用多模态模型在版面和 OCSR 等专门任务上存在可靠性限制，并采用领域工具与模型协作，而不是让一次长提示承担全部任务。[Doc2SAR，2025 修订版](https://arxiv.org/abs/2506.21625)

现代 harness 的关键不只是工具数量，而是明确状态、可检验目标、受约束动作、持久化交接和独立评价。Anthropic 的长任务研究强调规划、生成、评价的职责区分与结构化交接，同时讨论模型自评宽松的问题。这些是系统设计依据，并不意味着编码任务上的结果能够直接证明化学解析效果。[Harness design，2026](https://www.anthropic.com/research/harness-design-long-running-apps)

研究中可迁移的方法与采用边界：

| 来源 | 可迁移方法 | 本项目的采用边界 |
| --- | --- | --- |
| [MinerU2.5](https://arxiv.org/abs/2509.22186) | 全局版面与局部高分辨率读取分离 | 用于证据获取策略，不据此替换自研多肽模型 |
| [RxnCaption，2026 修订版](https://arxiv.org/abs/2511.02384) | 检测器预画框与索引，模型理解对象关系 | 宿主管坐标；反应解析成绩不能代表 SAR 正确率 |
| [MolParser，2025 修订版](https://arxiv.org/abs/2411.11098) | 专用 OCSR 与扩展表示处理 Markush | 能识别骨架不等于已正确组装全部成员并关联活性 |
| [Managed Agents，2026](https://www.anthropic.com/research/managed-agents) | 稳定接口分离会话、模型推理与执行环境 | 采用状态投影、可恢复记录与工具契约；无需增加不受控代理数量 |
| [OPSIN 官方高级用法](https://github.com/dan2097/opsin#advanced-usage) | radical 与 wildcard radical 的不同表示 | 完整分子与片段的解析入口分开，连接位点必须显式 |

这些文献采用不同数据、任务和指标，不能排成一个统一的“最先进”榜单。本项目应通过独立的真实多肽/环肽 SAR 基准选择机制和模型。

## 已实现的控制闭环

1. 全文测量证据发现：视觉检查页面中的实验、计算、预测、ADME 与药物性质结果；原生文本不再作为是否值得查看页面的唯一入口。读取失败作为缺口，不当成无数据。旧页面清单会先刷新来源类型，区分独立结构图、结果行、名称和模板成员，避免为表格行反复寻找不存在的独立结构图。
2. 结构局部证据：检测只获取几何，不隐式重跑识别、身份关联和组装。宿主提供实际坐标与标记裁剪，模型读取目标编号、附近测量、单位和归属；紧裁剪不足时才扩大上下文。相互矛盾的编号保持待核验。
3. 主体与测量绑定：观察保存 subject、endpoint、target、unit、source kind、原文和页面来源。重复编号对应不同分子时禁止直接把活性复制到所有结构。
4. 缺口驱动恢复：页面遗漏、局部证据不足、无结构的结果行、未组装的骨架、名称解析失败分别对应可用动作。模型只能选择宿主列出的动作，不能自行生成输入路径或框坐标。轮数、动作数和重复尝试都有上限；昂贵的页面操作按页去重，不能为同一页每个缺失编号重复整页识别。
5. 可恢复执行：记录动作、失败、预算和输入摘要，保存 checkpoint；恢复操作生成派生任务，不覆盖原任务。模型规划服务失败时只进行一次降级决策，宿主回退筛除纯人工动作，优先保留结果读取进度；规划和执行服务均不可用时明确记录失败并保留 checkpoint。新派生任务拥有新动作预算，原任务尝试历史继续用于避免重复；同一任务的 checkpoint 恢复保留已用预算。已人工修改字段有锁与来源标记。
6. 人工纠错：编号、结构、测量可改；可以添加化合物、添加科学测量列、删除测量列、恢复上一版本，并重新提交缺失证据恢复。写入使用版本号检查与历史快照。

实现入口：`utils/sar_harness.py`、`utils/measurement_evidence.py`、`skills/name_resolution/skill.py`。运行提示不包含待测文档的编号、预期数值或特定片段答案。

## PubChem 与名称解析

本地 OPSIN 使用每次调用独立的临时目录，已以生产服务 UID 验证，避免工作目录不可写和并发固定文件冲突。本地 OPSIN 优先；只有明确名称需要外部消歧且本地解析失败时，才允许 PubChem。外部操作必须带原始名称与文档证据。多 CID 结果返回歧义，不取首个结果。完整化合物与待接枝片段使用不同契约：饱和分子不能凭空增加接枝位点；局部名称必须提供可确定的单一连接位点。

PubChem 官方要求每个用户、应用或组织最多 5 请求/秒，不提供绕过限额的 API key 或白名单；服务繁忙时还会动态收紧限制。[PUG REST](https://pubchem.ncbi.nlm.nih.gov/pcfe/docs/markdown/pug-rest.md)

实现采用共享文件锁、SQLite 缓存与共享反馈状态，默认全局串行 1 请求/秒；按最差 `X-Throttling-Control` 反馈降速，遵守 `Retry-After`，429/503 退避，403 冷却，限制重试。404 与歧义有不同缓存寿命，瞬时服务故障不缓存成永久无结果。官方明确要求参考最差服务实例反馈，并建议大批量使用下载服务。[Dynamic throttling](https://pubchem.ncbi.nlm.nih.gov/pcfe/docs/markdown/dynamic-request-throttling.md)

这些措施降低封禁风险，不能承诺共享出口 IP 在其他应用同时请求时永不触发限制。上线验证使用模拟运输与时钟；真实服务只做一次名称查询，没有压力测试。

## Markush 与片段

保留骨架、变量位点、片段和成员编号的关系。文字片段可经本地名称解析或受限 PubChem 操作转为带显式连接位点的图，再使用图操作组装。全文完整名称可为缺失结构提供单独的候选图，用户可在编辑器检查后保存。与现有模型图冲突时，保留模型原始候选、撤销“已解决”输出，不能静默用名称图覆盖。缺位点、缺片段、剩余通配原子、意外断开产物或声明分子式冲突时不能发布为完整分子。结果关联只能使用明确的成员身份或图身份，不能按组装顺序、分子式或表格顺序猜配。

当前具有局部与组装后视觉审核，并加入全文实验名称的独立本地图核验。名称与组装图冲突时禁止发布该组装候选；没有可解析名称时明确记录独立证据缺失。实际回归中，16 个视觉审核接受的候选全部与独立名称图冲突，被新增检查拦截。这也说明相同模型二次判断会共享偏差，视觉审核通过数不等于化学正确数。仍需盲标注基准检查名称本身、连接位置、键型与立体化学。

## 多肽和环肽的优先契约

保留当前生产自研 MolSight 权重、分支与策略，增加模型版本摘要和输入来源记录。模型裁决通过只记录为视觉审核接受，不自动标记为独立正确性确认。前端补框继续调用现有结构服务，不能用通用语言模型替代专用图像识别模型。

序列证据必须包括非天然单体、端基、修饰、交联、环化连接与立体信息。裸单字母序列仅能产生候选，不覆盖图像模型图。新增 typed monomer/connection 图核验操作，明确保留未识别单体、部分覆盖与超时状态；图往返一致仅证明该图在工具内自洽，不能证明与原图一致。普通图相似度不再作为科学正确性的通过证据。

建议验收维度分别报告：线性肽、头尾环肽、侧链环肽、多环、非天然残基、N-甲基化、端基修饰、立体化学、跨页身份和测量关联。需使用与训练集隔离的真实文献图及人工金标准，不能拿开发集成绩声明线上正确率。

## 前端交互

PDF 连续滚动，按邻近页渲染，缓存受像素预算约束；服务端页面预览先显示。来源图用于定位，识别图用于结构编辑；图片采用平面布局。用户补框为绿色，与系统定位框区分，补框可选择结构、结果表格或骨架片段。表格提取保留未知归属记录，不能为无结构的结果凭空生成 SMILES。科学列保留单位、靶点和实验/预测区别，同列不同来源数值不能静默覆盖。

## 验证与限制

后端当前 65 项独立测试通过，覆盖坐标、局部证据归属、严格表格契约、Markush 缺失/连接错误、PubChem 模拟限流、编辑版本、恢复预算与多肽图契约。另外 11 项既有保存/API 合约测试、5 项静态交付测试通过。前端生产构建通过。浏览器回归覆盖连续阅读、同页框切换不重绘、PDF 单次下载、高 DPI、卡片/表格联动、结构编辑入口、补结构框、补表格框、测量保存、版本恢复、手机端布局和 Jobs 按钮可见性。线上原任务只读巡检无页面异常，本机首个 PDF 画布约 0.34–0.87 秒显示；这不是公网冷缓存延迟保证。
