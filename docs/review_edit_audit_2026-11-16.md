# 结果编辑审计与恢复

参考 Airtable 的记录修订时间线和快照恢复，结果工具栏新增 **History**。本次实现覆盖结果记录的保存入口，包括化合物 ID、结构、活性/ADME、增删记录和动态测量列。个人浏览器的列宽、显示顺序等视图偏好不作为科研数据版本。

官方参考：
- [记录级修订历史](https://support.airtable.com/articles/3516802427-record-level-revision-history-in-airtable)：作者、时间和修改内容。
- [快照恢复](https://support.airtable.com/articles/2163132802-taking-and-restoring-snapshots-in-airtable)：整体版本恢复。

## 用户交互

- History 侧栏按时间倒序展示保存；支持按化合物筛选和按字段/值搜索。
- 每条保存展开可见稳定记录 ID 所对应的字段前后值；重名化合物不会合并。
- 分子原始数据默认折叠，按需查看结构与文本。
- 单元格、整条记录、整份结果分别可恢复；已删除记录可单独找回。
- Restore this version 使用该次保存之后的数据；Restore before this change 使用保存之前的数据。
- 先预览范围，再确认写入。恢复本身生成新版本，记录被恢复事件的 ID；既有历史不删除。
- 单字段恢复保留其他后来修改，并同步测量纠错覆盖层。SMILES/坐标等耦合修改必须恢复整条记录。
- Export log 下载 JSON，保留时间、来源、revision、restore_of 及全部字段差异。

## 存储和一致性

`record_revisions/` 每个已提交事件保存前后完整记录、字段差异、时间、来源和前后内容 SHA-256；兼容旧格式的修改前快照。旧事件之后的状态从相邻快照推导，最后一条从当前数据推导；未记录的旧作者不会被补造。

写入由任务级跨进程文件锁串行化。恢复必须携带 base_revision；版本过期返回 409。保存检查记录 ID 唯一性，避免审计误配。CSV 和事件各自以临时文件和重命名发布；任务持久化报错时回滚 CSV，不发布成功审计事件。任务版本已提交但日志尚未重命名时，读取历史可完成 prepared 事件发布。

边界：当前任务元数据与 CSV/事件文件不属于同一数据库事务；这些措施不等于全系统断电原子性。当前哈希用于内容核查，不是签名，也不是管理员不可篡改的合规审计。需要更强保证时应统一使用数据库事务及独立的追加式审计存储。

## 差异判定修正

相同内容再次保存直接返回当前 revision，不改写 CSV、不创建快照。CSV 补齐的空字段、缺失值与空字符串、JSON 排版或对象键顺序、锁定字段列表的顺序和重复项、测量值从已有来源证据展开，都不算新的数据修改。Molfile 标题和程序头变化不计入结构修改，坐标与连接表变化仍会记录。个人视图中的行顺序不作为记录内容修改。

清空原本非空的值仍是修改；稳定记录 ID 的新增与消失分别是添加、删除。界面显示 Added / Deleted / Modified 数量，并可按操作筛选。撤销添加会明确提示移除新增记录。

读取旧日志时重新计算差异，过滤原先误报的空字段变化；未修改的记录不显示，整次没有变化的保存不显示，也不作为 Undo 的目标。原始快照文件保留。

修正验证：111 项后端测试和 16 组浏览器回归通过。SR 任务原先显示 34 条修改的一次保存，重新计算后为 18 条；另一次为 1 条。生产验证仅查看历史，没有执行恢复。

## 身份与保留

平台当前没有认证用户模型。浏览器生成本地会话标识，服务端仅记录其哈希短标签；它不能证明自然人身份。无会话的 API 调用明确标为作者未知。历史旧数据也明确标为作者未记录。未来认证接入后，应由服务端认证上下文提供用户 ID，不信任客户端自行声明的用户名。

当前新增审计没有自动过期或用户删除接口，随任务文件持久保存；部署备份必须包含任务目录。未认证条件下，不应将当前功能描述为已具备用户级访问控制或监管合规。

## 验证

后端测试覆盖：字段差异、重复化合物名、重复记录 ID 拒绝、删除恢复、单值恢复保留后续修改、测量覆盖层、恢复追加事件、旧格式读取、冲突拒绝和持久化失败回滚。浏览器隔离测试验证预览不写入、取消、确认恢复、版本参数、筛选和键盘关闭。实际 SR 任务只读验证时间线、恢复预览、导出、桌面和手机布局，没有执行生产数据恢复。
